# 트랜잭션 안 외부 호출

## 문제
```
트랜잭션 시작 (DB 연결 1개 점유)
  → 외부 API 호출 (결제사, AI, 메일 …)   ← 응답을 기다리는 동안 연결을 계속 잡고 있음
  → DB 저장
커밋 (연결 반납)
```
- 외부 API가 느려지면 요청마다 DB 연결이 하나씩 묶인다. 풀 크기만큼 동시에 멈추면 **외부 API와 무관한 모든 API가 멈춘다.** → [[커넥션 풀 크기 산정]]
- HTTP 클라이언트의 **기본 타임아웃이 무제한**인 경우가 많다(axios 기본 `timeout: 0`). 그러면 응답이 안 오는 순간 영원히 묶인다.
- 트랜잭션이 길어지면 잡고 있는 행 락도 오래 유지된다.

## 대응 (쉬운 것부터)
1. **외부 호출에 타임아웃**을 건다. 동작은 그대로 두고 무한 대기만 막는다. 위험이 가장 낮다.
2. **외부 호출을 트랜잭션 밖으로** 뺀다: 상태를 "처리 중"으로 저장 → 커밋 → 외부 호출 → 결과를 새 트랜잭션으로 반영. 구조 변경이라 검증할 게 많다.
3. 결제처럼 외부와 우리 DB의 상태가 어긋날 수 있는 흐름은 상태 기계·보상 처리로 다룬다. → [[결제 상태 기계]] · [[Saga 패턴]]

## 결제에서 타임아웃을 걸 때 주의
- 승인 요청이 타임아웃 나도 결제사 쪽에서는 **승인됐을 수 있다**("모름" 상태). 실패로 단정하지 말고 조회하거나 망취소로 정리해야 한다. → [[재시도 전략]] 결제 재시도 절
- 그래서 타임아웃을 넣을 때는 망취소 경로가 타임아웃 상황에서도 도는지 같이 확인한다.
