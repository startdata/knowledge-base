# 선불전자지급수단 규제 (전자금융거래법) — 설계 제약 #stub

> [[이중기입 원장]] · [[에누리와 청구할인]] · [[복합결제 전부-또는-전무]] 와 연결.
> 세션: [[세션/leaf-결제개편/설계결정-서사]]

## 1. 무엇이 해당하나
고객이 **돈을 내고 충전한 캐시**는 선불전자지급수단 발행에 해당할 수 있다. 대가 없이 준 무상 포인트(가입 축하 100P)는 해당하지 않는다. 2024년 9월 시행 개정법이 선불업 규제를 강화했다(등록 의무 확대, 선불충전금 100% 별도관리, 이용자 우선변제). B2B도 예외가 아닐 수 있다.

## 2. 의무 → 설계 제약
| 의무 | 제약 |
|---|---|
| 유상 충전금과 무상 포인트 구분 | 계정(`account_type` POINT/CASH)과 전표를 **분리**. 합산 잔액만 보이는 구조 금지 |
| 환급은 유상 잔액만 | 사용 시 어느 계정에서 얼마를 뺐는지 전표에 기록. **차감 순서(무상 먼저/유상 먼저)는 약관 결정** |
| 이용자 환급 요청 응대 | 캐시 → 계좌 이체 경로(`REFUND_OUT`). 고객 환불과 별개 |
| 선불충전금 별도관리(신탁·예치·지급보증)와 대사 | 발행잔액(전체 CASH 부채)을 원장에서 즉시 산출. 예치 잔액과 일 대사 |
| 유효기간·소멸 제한 | 유상 캐시 소멸 규칙은 무상 포인트와 다르게 |
| 거래기록 보존·이용자 조회 | 기록 원칙 동일 + 조회 API |

## 3. 부가세
충전 시점은 공급이 없어 선수금(비과세). 캐시를 써서 결제하는 시점에 과세. 월렛 전표에서 CHARGE는 부채, CAPTURE는 매출 인식 트리거로 정산이 구분해야 한다.
