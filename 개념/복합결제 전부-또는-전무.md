# 복합결제 전부-또는-전무 (Split Tender, All-or-Nothing)

> [[결제 상태 기계]] · [[이중기입 원장]] · [[멱등성]] 와 연결.
> 세션: [[세션/leaf-결제개편/설계결정-서사]]

## 1. 가장 흔한 사고: 포인트는 빠졌는데 카드가 실패
포인트를 먼저 차감하고 카드 승인을 시도하는 순진한 구현에서 생긴다. 되돌릴 수 없는 것(외부 승인)과 되돌릴 수 있는 것(내부 잔액)의 순서 문제.

## 2. 실행 순서
1. **내부 수단(포인트·캐시)을 먼저 선점(HOLD)** — 로컬 트랜잭션. 실패하면 아무 일도 없다.
2. **외부 수단(카드) 호출** — 실패하면 1의 HOLD를 해제(RELEASE).
3. 외부가 확정되면 HOLD를 확정(CAPTURE, 실차감).
전부 성공해야 결제 확정, 하나라도 실패하면 전부 해제. 이미 확정된 외부 분담이 있으면 `COMPENSATING`으로 두고 취소 명령을 낸다(취소가 끝날 때까지 실패로 내리지 않음).

## 3. 고아 HOLD
선점 후 확정도 해제도 안 된 것. 고객 포인트가 묶인다.
- 초안의 "1시간 초과 자동 해제"는 **즉시 확정 수단(카드) 전용 값**이다. 포인트 + 가상계좌(입금 대기 7일) 복합결제에서 1시간 뒤 HOLD를 풀면, 3일 뒤 입금됐을 때 확정할 HOLD가 없다.
- 판정은 **"형제 분담이 전부 종단 상태인데 HOLD만 남은 경우"**로, 시간은 보조. HOLD 만료 시각은 분담별로 그 결제의 가장 긴 리드타임 + 여유.
- 지연 확정 수단과 내부 수단의 복합결제를 허용할지 자체가 결정 사항.

## 4. 환불: 배분 순서와 실행 순서는 별개
| | 배분(누구에게 얼마) | 실행(무엇부터) |
|---|---|---|
| 결제 | 포인트 → 캐시 → PG | **내부 먼저 HOLD** |
| 환불 | 정책(약관): 외부 우선 환원 또는 포인트 우선 환원 | **외부 먼저** |
PG 취소는 예약할 수 없다. 포인트를 먼저 복원하면 PG 취소 실패 시 고객이 포인트를 써버렸을 수 있다. 외부 취소가 실패하면 `PARTIALLY_FAILED`는 오류가 아니라 **정상 상태** — 실패한 것만 재시도, 성공한 것을 되돌리지 않는다. 배분 순서는 약관 명시 사항.

## 5. 월렛을 별도 모듈로 두면
결제 모듈은 포인트도 외부 수단처럼 **멱등키 붙인 포트 호출**(hold/capture/release)로 다룬다. HOLD가 로컬 트랜잭션이 아니게 되므로 실패 시 RELEASE 보상이 필요하지만, 오케스트레이션은 한 가지 방식으로 단순해진다.
