# 관제봇 사이클 순서별 트레이싱 (2026-08-03)

## 문제·배경
- alertbot·tempbot의 Langfuse 트레이싱이 **LLM 호출 지점에만** 걸려 있었다 — 배치 사이클의 단계(수집→분류→판단→발송)가 어떤 순서로 얼마나 걸리는지 타임라인이 없음.
- 결정적(LLM 0콜) 단계 — panel 노드, A/B트랙 탐지, 규칙 판정 — 는 Langfuse에 아예 안 보였다.
- 트레이싱·Langfuse 세팅은 준님 담당 영역이라 직접 수정.

## 접근·의사결정
- **span은 LLM 없이도 기록된다**는 점을 이용 — 사이클 전체를 부모 트레이스(`alerter:cycle` / `alerter:tempbot:cycle`)로 열고, 각 단계를 자식 span으로. 단계 결과(건수)는 `span.update(output=...)`.
- **propagate_attributes 중첩 함정**이 핵심 결정을 강제: 기존 후보별 독립 트레이스(judge)와 tags 지정 generation(tempbot router/efficiency/debate)을 그대로 사이클 안에 넣으면 propagate가 부모 트레이스 이름·태그를 덮는다 → 전부 **child 모드**(속성 미설정, 관측 이름만)로 전환. → [[Langfuse]]
- tempbot run_cycle(~250줄)은 전면 재들여쓰기 대신 **얇은 트레이스 래퍼 + 본문 분리**(`_cycle_stages`)로 감쌈. 들여쓰기 꼼수(try 안 얕은 with)를 시도했다가 팀 스타일 위반이라 정석 재들여쓰기로 교정.
- 대시보드 영향을 커밋 메시지에 명시: 기존 태그(judge/router/efficiency) 트레이스 필터는 새 데이터에 안 걸림 — `alertbot`/`tempbot`+`cycle` 태그로 전환 필요.

## 결과 (실측 — dev DB 실사이클 + 가짜 Langfuse 클라이언트 캡처)
```
alerter:tempbot:cycle [342ms]
 ├ track:a  [124ms] {candidates,rejected,routed}   ← LLM generation들이 자식으로
 ├ report:a [0ms]   {pages}
 ├ track:b  [77ms]  {candidates,rejected}
 └ panel    [122ms] {confirmed,watching,excluded}  ← LLM 0콜 단계가 처음으로 관측에 등장
alerter:cycle
 ├ collect:<시나리오> → classify → judge(└ judge:<시나리오> └ judge:llm) → send → recovery
```

## 검증
- traced_span 단위 테스트 3건(no-op·output·트레이스 속성 불변) + judge/tempbot 트레이싱 계약 테스트 갱신 — 전체 1,413건 통과.
- dev DB 실사이클을 가짜 클라이언트로 캡처해 트리·타이밍 육안 확인 (배포 전 시연).

## 후속 — efficiency 고아 트레이스 수정 (2026-08-04, fix/trace-thread-context)
- **증상 vs 원인**: "track:c span이 텅 빔"으로 보고됐으나, prod Langfuse API 실조회 결과 track:c는 정상(C트랙이 라우터 미니멀=LLM 0콜이라 안이 빈 것 + 사이클의 40%를 차지하는 게 오히려 보임). **진짜 버그는 efficiency generation 전량(15건)이 태그 없는 고아 트레이스로 이탈** — 사이클 안 분포 router 27·debate 13·efficiency 0으로 확인.
- **원인**: efficiency 심화만 dispatch **스레드 풀**에서 호출 — OTEL 컨텍스트([[contextvars]])가 워커로 전파되지 않음. 메인 스레드의 router/debate는 정상.
- **조치**: `traced_generate(bind_context=True)` — 빌드 시점(사이클 트레이스 안) 컨텍스트 캡처, 호출마다 `ctx.copy().run()`(동시 진입 금지 대응). efficiency 배선에만 적용.
- **의도적 한계**: 부모가 사이클 루트로 고정 — track:c span **아래** 종속시키려면 dispatch(`pipeline.py`, 팀 파일)에서 태스크별 전파 필요 → 팀 협의로 남김.
- **검증**: 스레드 풀 8병렬 회귀 가드(컨텍스트 유지+관측 8건) + 전체 1,516건 통과. 커밋 `cd29d0a` push(PR 미생성).
